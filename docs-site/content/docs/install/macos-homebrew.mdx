# macOS

## What you will do

Install Codifix through Homebrew or the native `.pkg`, configure global and
project settings, and verify the service.

## Homebrew

```bash
brew tap 3vilM33pl3/codifix https://github.com/3vilM33pl3/codifix
brew install 3vilM33pl3/codifix/codifix
codifix wizard --global
cd /path/to/project
codifix wizard --dry-run
codifix wizard
codifix service enable
codifix doctor
codifix health
codifix tui
```

For unreleased changes, use:

```bash
brew install --HEAD 3vilM33pl3/codifix/codifix
```

## Native .pkg

The [v2.1.0 release](https://github.com/3vilM33pl3/codifix/releases/tag/v2.1.0)
publishes separate native installers and matching checksums:

- Intel Mac: `codifix-2.1.0-macos-x86_64.pkg`
- Apple Silicon Mac: `codifix-2.1.0-macos-aarch64.pkg`

These standard packages require separately configured PostgreSQL/pgvector. If
Memory already has a bundled runtime, choose the architecture-matched
`-application-update.pkg` instead: it preserves that runtime, its data and helper
launcher. The standard package refuses to overwrite a bundled runtime. Do not
switch an existing bundled installation to Homebrew as an implicit migration.

Download the package for your Mac, run it, then continue with the same setup
commands:

```bash
codifix wizard --global
cd /path/to/project
codifix wizard --dry-run
codifix wizard
codifix service enable
codifix doctor
codifix health
codifix tui
```

If a release notes that the `.pkg` is unsigned, macOS may require an explicit
Open action from Finder or System Settings. Homebrew remains the preferred path
when you want the fewest Gatekeeper prompts.

## Verify

```bash
memory --version
codifix service status
codifix status --project <project-slug>
```
