# macOS

The Codifix 3.0.0-rc.1 macOS packages are not published yet. The existing
v2.1.0 release is the previous Memory Layer product; its assets are not
Codifix installers. Homebrew currently provides a HEAD formula only. There is
no stable Codifix formula or published candidate archive and checksum yet.

## Homebrew

The formula can be used for development from the current source checkout:

```bash
brew tap 3vilM33pl3/codifix https://github.com/3vilM33pl3/codifix
brew install --HEAD 3vilM33pl3/codifix/codifix
```

This builds the current source; it is not a packaged 3.0.0-rc.1 release
install. Do not use `brew upgrade` as a v2-to-v3 migration path.

## Native packages

After publication, the expected standard package names are:

- Intel Mac: `codifix-3.0.0-rc.1-macos-x86_64.pkg`
- Apple Silicon: `codifix-3.0.0-rc.1-macos-aarch64.pkg`

The matching packages ending in
`-macos-x86_64-application-update.pkg` or
`-macos-aarch64-application-update.pkg` are for updating an existing Codifix
installation. They do not migrate Memory Layer. Standard packages require
separately configured PostgreSQL/pgvector; application-update packages preserve
the Codifix runtime they update. The candidate packages are not yet published,
so these filenames have no available checksums to verify.

Download only from the published Codifix 3.0.0-rc.1 release and verify its
matching checksum. For an existing Memory Layer installation, first follow the
[Update guide](/docs/install/update) and the
[release-specific reinstall procedure](https://github.com/3vilM33pl3/codifix/blob/main/packaging/CODIFIX-3-REINSTALL.md).
Do not replace an existing bundled runtime with Homebrew as an implicit
migration.

After installing a published candidate, configure and verify it:

```bash
codifix wizard --global
cd /path/to/project
codifix wizard --dry-run
codifix wizard
codifix service enable
codifix doctor
codifix health
codifix tui
```

## Verify

```bash
codifix --version
codifix service status
codifix status --project <project-slug>
```
