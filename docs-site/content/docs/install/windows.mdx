# Windows

Codifix 2.1.0 publishes native Windows x86_64 **preview** artifacts:

- `codifix-2.1.0-windows-x86_64-build.1.msi`
- `codifix-2.1.0-windows-x86_64-build.1.zip`
- `codifix-2.1.0-windows-x86_64-build.1-server-tools.msi`

The packages include client/operator executables, Web assets and skills, not a
complete native PostgreSQL/PDS/Pi stack. The machine-level server-tools MSI does
not provision dependencies or start services. Full Windows parity and supervisor
acceptance remain unfinished; consult the release's exact verified capability list.

Windows ARM64 is not a release target yet.

## Native MSI

Download the MSI and matching checksum from the
[v2.1.0 release](https://github.com/3vilM33pl3/codifix/releases/tag/v2.1.0),
verify it, and run the installer. The per-user installer places
`codifix.exe`, the bundled web UI, skill templates, README, example config, and
PowerShell completion under `%LOCALAPPDATA%\Programs\Codifix`, then adds
its `bin` directory to the user `PATH`.

After installing:

```powershell
codifix --version
codifix wizard --global
codifix doctor
codifix health
codifix tui
```

The native package does not include PostgreSQL. Use an existing PostgreSQL
server with pgvector, a local database you manage yourself, or the bundled
Docker Compose stack.

## Portable ZIP

Use the ZIP when you want to inspect or run the binary without installing the
MSI. Extract the archive, add its directory to `PATH`, then run:

```powershell
codifix --version
codifix doctor
```

## Docker Desktop

The bundled Compose stack runs under [Docker Desktop](https://docs.docker.com/desktop/setup/install/windows-install/):

```powershell
git clone https://github.com/3vilM33pl3/codifix
cd codifix
docker compose up
```

That brings up PostgreSQL with pgvector, the Codifix service, and the web
UI at [http://localhost:4040](http://localhost:4040). Load the showcase project
from inside the container:

```powershell
docker compose exec codifix codifix demo
```

## WSL2

For Linux-native shell behavior, TUI workflows, and file watchers, use an Ubuntu
[WSL2](https://learn.microsoft.com/windows/wsl/install) distribution and follow
the [Linux / Debian install](/docs/install/linux-debian) inside it.

Repositories are reachable from WSL2 under `/mnt/c/...`, though keeping active
repositories inside the WSL2 filesystem is faster and works better with file
watchers.
