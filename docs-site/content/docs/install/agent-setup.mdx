# Let your agent set you up

Use these prompts with a coding agent that can inspect your machine and run
commands. For an existing company installation, use [Team setup](/docs/team-setup)
rather than asking an agent to create another service/database.
Codex Desktop users can add the [Codex plugin](/docs/codex-plugin) after setup.

## Prompt for installing

<PromptBox>

```text title="Install prompt"
Install Codifix on this machine using the current platform guide at
https://codifix.dev/docs/install and the exact published release inventory.

First inspect the OS, architecture and existing installation. The current
Codifix package is 3.0.0, the stable release; do not select the historical
Memory Layer release through a generic "latest" installer. Verify checksums
and explain the unsigned-package/platform limits. Homebrew builds the checksum-pinned v3.0.0 release source.

If Memory Layer or an existing named area is present, use the release-specific
update procedure before changing it. Preserve configuration, credentials,
state, data and recovery executables. Confirm the exact installation to change.

For a fresh standalone service, provision or verify PostgreSQL with pgvector
before running codifix wizard --global. Use protected secret configuration;
never put credentials in source control. Configure optional paid providers
only when requested. Make Go available for repo-local workflow skills.

Preview repository setup with codifix wizard --dry-run, preserve existing
.codifix and .agents customizations, then apply the reviewed setup. Start only
the intended service using its platform guide. Verify codifix --version,
codifix doctor, codifix health, codifix urls and the selected project status.

Report the exact version/source, installation and config paths, validation,
and next action. Stop for any unrequested destructive change.
```

</PromptBox>

## Prompt for initializing your repository

<PromptBox>

```text title="Initialize repo prompt"
Configure this repository for the existing Codifix installation. Inspect the
repo marker, .agents files, user-local config and operator-owned area routing.
Verify the intended area and project before any read or write.

Do not reinstall the package, create a database, reinitialize Git, delete
existing configuration or overwrite custom instructions. Run codifix health
and codifix doctor, then codifix wizard --dry-run. Apply only the reviewed
repo-local setup with codifix wizard, preserving customizations.

Verify codifix status --project <project-slug> --json. Make Go available for
the shared workflow helper. Do not import commits, scan repositories, enable
providers or grant external expertise access merely to initialize the repo.

Report the selected area/project, changed and preserved files, health checks,
and any remaining issue. Follow https://codifix.dev/docs/daily-workflow next.
```

</PromptBox>
