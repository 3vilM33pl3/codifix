# CLI: repository, evidence, and search

These commands maintain the evidence Codifix uses for retrieval, provenance, and graph-aware context. They are usually run after onboarding, large refactors, provider changes, or repository history imports.

| Command | Writes | Purpose |
|---|---:|---|
| `codifix commits` | Yes | Import and inspect git commit history. |
| `codifix repo` | Yes | Build and inspect the repository index. |
| `codifix graph` | Yes | Extract and inspect the project code graph. |
| `codifix embeddings` | Yes | Rebuild and maintain embedding spaces. |
| `codifix bundle` | Mixed | Export and import shareable project codifix bundles. |

## `codifix commits`

Import git history when commit context matters for future questions.

```bash
codifix commits sync --project memory
codifix commits sync --project memory --limit 100 --dry-run
codifix commits list --project memory --limit 20
codifix commits show <commit-hash> --project memory
```

Commit sync is evidence, not curation by itself. Pair it with query, scan, or explicit memories when decisions should become durable project knowledge.

## `codifix repo`

The repository index records files and metadata used by scan and provenance workflows.

```bash
codifix repo index --project memory
codifix repo index --project memory --since 2026-04-01 --dry-run
codifix repo status --project memory --json
```

Run it after major file moves or when scan/provenance output looks stale.

## `codifix graph`

The graph command extracts parser-backed code symbols, references, and edges.

```bash
codifix graph extract --project memory
codifix graph extract --project memory --force --text
codifix graph status --project memory
```

Graph data helps query connect memory facts to code structure. It is especially useful after refactors where names or modules move without intended behavior changes.

## `codifix embeddings`

Embedding commands maintain semantic search spaces.

```bash
codifix embeddings list
codifix embeddings activate voyage-code
codifix embeddings reindex --project memory --dry-run
codifix embeddings reembed --project memory --backend voyage-code
codifix embeddings prune --project memory --dry-run
```

Use `list` before rebuilds. `reindex` rebuilds chunks and embeddings, while `reembed` fills configured embedding spaces without rebuilding chunks.

## `codifix bundle`

Bundles move project memory between systems or preserve a point-in-time export.

```bash
codifix bundle export --project memory --out memory.mlbundle.zip
codifix bundle import --project memory ./memory.mlbundle.zip --dry-run
```

Review bundle contents before import. Treat bundles as sensitive project data.
