# CLI: service and health

Use these commands before debugging query, TUI, watcher, MCP, or embedding behavior. Most symptoms start with one of three causes: the service is not reachable, config points at the wrong service, or PostgreSQL/pgvector is not ready.

| Command | Writes | Purpose |
|---|---:|---|
| `codifix service` | Mixed | Run or manage the HTTP backend and web UI. |
| `codifix status` | No | Show aggregate diagnostic status for a project. |
| `codifix doctor` | No | Inspect config, database, service, tools, and environment. |
| `codifix health` | No | Check backend API health. |
| `codifix watcher` | Mixed | Inspect and flush automation state. |

## `codifix service`

The service hosts the HTTP API, web UI, and optional Streamable HTTP MCP route.

```bash
codifix service run
codifix service enable --dry-run
codifix service status
codifix service enable
codifix service disable
codifix service restart-all
codifix service ensure-api-token
```

`codifix service run` is a foreground command. A development `cargo run --bin codifix -- service run` should not daemonize itself. Packaged installs use systemd on Linux or launchd on macOS for background operation.

Development defaults commonly use `127.0.0.1:4250`; packaged installs commonly use `127.0.0.1:4040`. Check your config and `codifix service status` instead of assuming a port.

## `codifix status`

Use status for a combined project-level view.

```bash
codifix status --project memory
codifix status --project memory --json
```

Status is the fastest single command for checking service reachability, project config, watcher state, MCP status, and common doctor diagnostics.

## `codifix doctor`

Doctor performs a deeper environment inspection.

```bash
codifix doctor
codifix doctor --project memory
codifix doctor --json
codifix doctor --fix
```

Run it after config edits, package upgrades, database migrations, token changes, or provider changes.

## `codifix health`

Use health to confirm the backend responds; use `codifix status` to confirm the expected project has data.

```bash
codifix health
```

If health is green but a project command is empty or unauthorized, verify the project slug and credential with `codifix status --project <slug>` and `codifix doctor --project <slug>`.

## `codifix watcher`

Watchers inspect background work and can flush queued work when supported.

```bash
codifix watcher --help
codifix watcher status --project memory
```

Treat `codifix watcher flush` as a write operation. Capture logs before changing queue state when diagnosing failures. The historic `memory automation flush` spelling is no longer a command.
