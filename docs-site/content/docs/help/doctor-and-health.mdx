# Doctor and health

`codifix doctor` checks configuration, database, providers, skills, and environment readiness.

`codifix health` checks whether the backend service is reachable.

`codifix status --project <project-slug>` combines service, project, watcher, MCP, and diagnostic state into one payload.

## When to run each

| Situation | Command |
|---|---|
| Fresh install | `codifix doctor` then `codifix health` |
| Service outage | `codifix health` |
| Agent cannot find project memory | `codifix status --project <project-slug>` |
| Provider or embedding problem | `codifix doctor` |
| Repo-local skills are missing or stale | `codifix doctor --fix` |

## Skill checks

Doctor compares repo-local `.agents/skills/` with the local installed template and, when reachable, the current GitHub skill bundle. `codifix doctor --fix` downloads the GitHub bundle, repairs missing or outdated Codifix-owned skills, and falls back to the installed template when offline.

The TUI and Web UI Skills tabs expose the same inventory and repair path when you want to inspect the exact `SKILL.md` file before fixing it.
