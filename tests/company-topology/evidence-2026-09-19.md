## Trial failures fixed without weakening guards

- The negative CA test originally inherited `NODE_EXTRA_CA_CERTS` when it omitted
  `ca`. It now supplies an explicit empty trust-root array, so rejection tests
  actually exclude the trusted fixture CA.
- OpenSSL created the public CA as mode 0664 under host umask 0002. The real
  operator correctly rejected it as `unsafe_private_file`. Only the newly
  generated fixture CA is now chmod 0644; the operator's filesystem guards are
  unchanged.
- The initial synthetic label `repository` received upstream HTTP400
  `HandleNotAvailable`: the pinned PDS explicitly reserves it. A completely fresh
  fixture uses the non-reserved `space` label. No existing identity/journal was
  rewritten, ambiguous create was not retried under another identity, and no
  upstream security bypass or PDS fork was added.

All failed trial projects were cleaned. Only the final combined invocation is
the successful evidence above.
