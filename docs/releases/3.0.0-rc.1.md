# Codifix 3.0.0-rc.1

**Release candidate preparation.** This note is being prepared for Codifix
3.0.0-rc.1. The candidate has not yet been published or installed, and
cross-platform release acceptance is still pending. No release hashes or
platform acceptance results are claimed here.

## What changes

Codifix 3.0.0 is a breaking technical rename from Memory Layer. Product-owned
commands, package identities, service names, configuration paths and federation
enrolment names use Codifix identities. The old Memory Layer packages are not
upgraded in place, and Codifix does not provide old command aliases. Treat the
move as an explicit single-user reinstall and cutover, following the
[release-specific reinstall procedure](../../packaging/CODIFIX-3-REINSTALL.md).

The rename preserves canonical and received knowledge, `memory_entries`,
existing content and attachments, and established identifiers. Existing
federation records and their signed history remain available as historical
evidence. Retirement disables old subscriptions and contribution bindings,
blocks unfinished source and publication work, invalidates old leases and
rotates the reviewed gateway epoch. Old queued, accepted and proposed payloads
are retained with their original bindings; they are not moved into a new
enrolment or published as new work. Participating instances require fresh,
explicit enrolment and sharing grants before federation resumes. See the
[federation cutover operator guide](../../scripts/codifix-cutover/README.md).

The cutover keeps area topology and canonical/auth/area identifiers intact.
Database names and roles remain unchanged except for the exact product-owned
macOS onboarding names documented in the reinstall procedure. Previously
published releases, their artifacts, signatures and release notes are unchanged.

## Reinstall and recovery

Back up and verify a matched recovery set before retiring the old installation:
database snapshot, configuration, environment files, state, credentials, service
definitions, active-state inventory and exact old executables. Keep the old
release packages and manifests unchanged. Stop and inventory old writers,
watchers, schedulers and federation workers before the cutover. Do not purge old
configuration or state, and do not enable previously inactive services as part
of reinstall. The detailed procedure covers Linux, macOS and Windows-specific
steps and recovery limits.

## Platform status

Windows packages remain preview packages. The release-specific installer ledger
reserves Windows build 1 for this candidate (MSI version `3.0.1`); this
allocation does not establish package acceptance. Native macOS UI and California
deployment acceptance are not claimed by this candidate note. Package builds,
installation, state transfer and platform acceptance remain to be completed and
reported from release evidence before publication.

## Earlier releases

This candidate does not rewrite or replace the 2.1.0 release note, previously
published packages, signatures or release manifests.
