Status: **B2 and B3 complete at the pure domain/policy/model scope**. The

roadmap remain incomplete. This follows the [publication domain increment](2026-09-08-publication-domain.md).

## B2: explicit permission intersection

Commit `b464b8a` adds `PublicationState::authorize_pull` and
`authorize_publication`, using current `mem_record::PermissionSet` without
modifying role presets, adding dependencies or changing service routes.

The caller needs exact-project local permissions, an explicit principal/project/
space/instance sharing grant, and the current independent gateway capability.
Read requires MemoryRead/Pull; publication requires MemoryRead + MemoryCurate +
BundleExport/Publish; tombstones additionally require MemoryDelete. Membership
changes require MemoryRead + AuthManage/ManageMembership and the configured
space authority. The actual record chooses the requirements, not a caller's
operation label. Read-only mode denies all writes.

Tests enumerate all 2048 combinations of today's 11 local permissions for read,
publication, tombstone and membership actions, and cover role presets, missing
grants/enrollment, wrong principal/project/space/instance, nil identities,
read-only writes, capability revocation and non-authority membership changes.
Policy inputs are not wire-deserializable; construction still does not establish
authentication. See the [mapping and integration contract](../../developer/architecture/federation-permissions.md).

## B3: all publication variants in shared conformance

Commit `5acbb3e` extends the existing Lean publication model and real Rust reducer
harness together. Five publication fixtures plus the nine untouched legacy
fixtures pass in both runtimes. The new cases cover immutable evidence, missing /
duplicate / cross-origin / wrong-kind references, proposal approval/rejection,
stale/closed/missing proposals, relation assertion/retraction and endpoint/type
stability, causal links, all three capabilities and authority self-protection.

The Rust harness round-trips every expanded delivery, verifies unchanged state on
all non-applied outcomes, compares accepted deliveries without loss, checks final
capability sets and projections, verifies retained evidence bytes/digests,
proposal status/accepted version and relation history, and compares replay with
the step-by-step result.

Rust-only regression checks also reject relocating an accepted record or assigning
its locator to a different record ID. These alias cases cannot be expressed by
the normalized Lean trace format, which derives locators from record IDs.

`PublicationInvariants.lean` proves causal dependency existence, publishing
membership for all data variants, evidence origin/space binding and reference
existence/scope, changed-binding rejection, proposals not rewriting existing
versions, origin/pending/causal resolution requirements, stale approval leaving
state unchanged, preservation of proposed content/author/evidence and origin
approval key, atomic version append plus resolution, rejection not appending
content, stable relation endpoints/type with next revision, and configured
membership authority. Earlier duplicate/version/state/revocation/replay proofs
continue to compile. No `sorry`, Mathlib, Aeneas or new axiom is introduced.

## Limits and next implementation boundary

The model abstracts non-nil UUIDs as natural numbers and uses a fixed representative
space/authority. Selected content fields vary; other wire fields/timestamps are
fixed by the fixture contract. Rust validates identifiers, counters, canonical
encoding, envelope integrity and reviewed snapshot bytes before the modeled
transition. Lean does not prove those parsers/hashes, human review, authentication,
the complete Rust implementation or deployment. The B2 local policy matrix is
tested exhaustively in Rust, not formally verified in Lean.

No new route, migration, production ingestion, deployment, credentials or external
documents changed. Local grants are not persisted or administered yet. A policy
success cannot be reused as a durable authorization receipt: current local grants
and gateway membership must be rechecked within the future transactional workflow.

Next is C/R1: durable local jobs and publication intent; serialized/fenced gateway
acceptance plus outbound intent; atomic receiver inbox/projections/cursor with
disposable PostgreSQL crash/retry tests. Production schema-version-2 ATProto wire
mapping and unknown-field compatibility must pass before external publication;
the unchanged six-record spike adapter does not establish that compatibility.
Gateway isolation/authentication, two independently operated instances, Web/CLI/TUI
parity, complete recovery, evaluations and paid-pilot gates remain open. Native
Spaces remains alpha/disposable-data only; no production substitution is implied.
