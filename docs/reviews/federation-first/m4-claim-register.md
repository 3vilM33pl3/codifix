## Evidence vocabulary

- **Positioning:** the founder-approved product direction; not an outcome.
- **Implemented:** code and its stated tests exist at the audited checkpoint.
- **Controlled demonstration:** a named synthetic or disposable workflow ran;
  not a customer installation, independent physical fleet or commercial result.
- **Observed development:** a real development experiment with the limitations
  shown; not an official held-out result or customer ROI.
- **Hypothesis / forecast:** a commercial, staffing, pricing or economic input to
  validate. Correct model arithmetic does not validate the input.
- **Future / gated:** work or authority still required. An unchecked release gate
  cannot be closed by a completed component test or a presentation revision.

## Dated technical source register

### T1 — ATProto and Memory responsibilities

**Decision: 10 September 2026; re-read 17 September.**
[ADR 0011](../../developer/adr/0011-atproto-federation-adapter.md), lines 28–63,
67–91 and 114–133; [repository verifier](https://github.com/3vilM33pl3/codifix/blob/b56292a19a12aa74b6e8d723c7a95b78f7b818cf/crates/mem-atproto-verify/src/lib.rs),
lines 56–65 and 105–155.

ATProto is an external record/repository adapter behind a neutral Memory domain.
DIDs, Lexicons/XRPC, signed content-addressed repositories and transfer primitives
do not provide Memory's authorization or immutable accepted history. Memory
keeps source/author attribution distinct from authenticated publisher identity.
The verifier checks an enrolled DID/key and signed repository inclusion; it does
not prove truth, freshness, current authorization or append-only history.

Native Spaces remains a separate compatibility candidate. Experimental Lexicons
are unpublished; no stable production namespace is claimed. MCP is local;
remote task interoperability is separate. The gateway remains a trusted authority
and an availability dependency, with no automatic failover or peer consensus.
