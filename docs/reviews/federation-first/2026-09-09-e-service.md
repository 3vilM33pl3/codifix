## Implemented

- The service lifecycle registers only its administrator-configured instance;
  handlers cannot select endpoints, secrets or trust roots. Stopping that
  lifecycle unregisters the API binding; disabled/no-op handles cannot remove
  another live registration.
- Five experimental local endpoints use the existing central authentication,
  exact-project authorization, browser CSRF and read-only guards. They expose
  local grants, status, source preview, publication review and selected retained
  context. All responses are `no-store`; errors omit database/transport details.
- Grant updates and local auth audit events commit together. Local permission,
  explicit sharing grants and gateway membership stay independent. Anonymous
  single-user reads do not inherit the owner's sharing grants.
- Migration 0037 makes review submissions retry-safe under concurrent delivery.
  Exact source comparison, evidence review, standing-consent subscription,
  deferred source capture and request/result identity commit together. Reviewer
  and time are server-stamped. Changed request-ID payloads, stale selections,
  modified evidence, wrong scope and unconfirmed standing consent fail closed.
- Review-owner scheduling is bounded and re-resolves each owner's current
  permissions. A background principal cannot lend its role to another user's
  queued publication. Gateway acceptance still rechecks remote authority.
- Retained context has explicit citation metadata and untrusted/offline/fresh-
  forwarding-policy flags. It preserves origin, publisher, original author,
  shared/source versions, locator/digest, evidence and frozen receipt policy.
  Proposal resolution retains the corrector's authorship while naming the origin
  owner's publication. Imported records remain outside implicit search, curation,
  embeddings and model calls.

## Remaining E work and limits

1. Explicit remote enrollment/member management and two independently administered
   installations. The local grant endpoint is not gateway enrollment.
2. Origin-owned proposal submission/approval wired through application transactions,
   without treating an imported correction as permission to rewrite a source.
3. Web/CLI/TUI clients, grant listing, per-stream consent controls, review inspection,
   proposal actions and useful synchronization/retry status.
4. The complete two-party browser/CLI/TUI journey, interrupted delivery/catch-up,
   revocation and recovery at those user-facing boundaries.

Reviews currently require standing future-update consent; one-shot publishing and
per-stream stop controls are not implemented. Disabled grants pause transmission,
not erase subscriptions or queued history. Queue counts belong to the caller;
the receiver cursor is not the latest remote published head or another receiver's
acknowledgement. Current local access can authorize retained offline copies even
after remote revocation; delivered bytes cannot be recalled. No external model is
invoked by this API. Release/security/recovery/legal/namespace gates stay open.
